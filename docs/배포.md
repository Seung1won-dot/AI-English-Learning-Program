# 배포하기

[← README로 돌아가기](../README.md)

모든 화면은 **로그인해야** 쓸 수 있고, 학습 기록은 계정마다 따로 저장됩니다.
친구에게만 열어 두려면 **`INVITE_CODE`를 설정**하세요. 코드를 아는 사람만 가입할 수 있습니다
(비워 두면 주소를 아는 누구나 가입 가능). **처음 가입한 계정**(또는 `OWNER_USERNAME` 아이디)이
계정 도입 전의 기존 기록을 이어받으니, 배포 후 주인이 먼저 가입하세요.

| 환경변수 | 설명 |
|---|---|
| `GROQ_API_KEY` / `OPENAI_API_KEY` | AI 키 (없으면 목업 모드) |
| `GROQ_MODEL` / `OPENAI_MODEL` | 사용할 모델 (선택, 기본값은 [`.env.example`](../.env.example) 참고) |
| `INVITE_CODE` | 가입할 때 필요한 초대 코드 (공개 서버 권장) |
| `OWNER_USERNAME` | (선택) 기존 기록을 이어받을 아이디. 비우면 첫 가입자 |
| `SECRET_KEY` | 로그인 세션 서명 키 — 긴 임의 문자열 (`python -c "import secrets; print(secrets.token_hex(32))"`). 비우면 DB 폴더의 `.secret_key` 파일에 자동 생성 |
| `SESSION_COOKIE_SECURE` | https 로만 서비스하면 `1` (로그인 쿠키를 https 에서만 전송) |
| `APP_PASSWORD` | (선택) 사이트 전체에 브라우저 비밀번호 창을 한 겹 더 건다. 계정이 있으니 보통은 비워 둔다 |
| `AI_TIMEOUT_SECONDS` | AI 응답 대기 상한(초, 기본 25). 넘으면 목업으로 대체해 서버가 멈추지 않게 함 |
| `DB_PATH` | 학습 기록 DB 경로 — 플랫폼의 **영구 디스크**로 지정 (예: `/data/learning.db`) |
| `PORT` | 서버 포트 (플랫폼이 자동 지정) |

## 배포 전 로컬 확인

Procfile 과 같은 명령을 내 PC 에서 돌려 보면 배포 환경과 거의 같게 확인할 수 있습니다 (macOS/Linux).

```bash
PORT=8000 SECRET_KEY=dev .venv/bin/gunicorn app:app --bind 0.0.0.0:8000 --workers 2 --timeout 60
```

`http://127.0.0.1:8000/healthz` 가 `{"ok": true}` 를 돌려주면 정상입니다. gunicorn 으로 실행하면 디버거는 항상 꺼져 있습니다.

## Render / Railway 등 (Procfile)

저장소를 연결하면 `Procfile`(`gunicorn app:app`)로 실행됩니다. 영구 디스크를 붙이고
`DB_PATH`를 그 경로로 지정하세요. 헬스 체크 경로는 `/healthz` 입니다.

## Docker

```bash
docker build -t english-world .
```

```bash
docker run -p 8000:8000 -v ew-data:/data -e SECRET_KEY=... -e INVITE_CODE=... -e SESSION_COOKIE_SECURE=1 english-world
```

컨테이너는 `DB_PATH=/data/learning.db` 로 실행되고, `/data` 볼륨에 기록이 남아 컨테이너를 다시 만들어도 유지됩니다.

> SQLite 는 파일 하나에 저장하므로 서버 인스턴스는 **1대**로 운영하세요.
> 로그인 실패 제한(10분에 10번)은 worker 메모리에 있어 재시작하면 초기화됩니다.

## 콘텐츠 수정

문제·어휘·오픽 질문은 `data/*.json` 입니다. 고친 뒤에는 형식 검사를 돌리세요 (오류가 있으면 종료 코드 1).

```bash
python scripts/validate_content.py
```
